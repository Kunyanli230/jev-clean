# Jev Clean v0.2

This release makes the existing local cleaning engine accessible without API
credentials and fixes baseline evaluation when removal changes CSV row positions.
It preserves `idac`, the YAML schema, the seven cleaning phases and the Jev policy.

## Scope and usage

`idac profile --input data.csv --config schema.yaml` reads the original snapshot,
reports quality counts and lists detected issues, evidence and authorized repair
previews. `--json` writes the complete JSON to stdout; `--output profile.json`
saves it to a new file. A profile does not create a clean run or mutate cells.
All phases inspect the original values in order, retaining unresolved issues for
dependency checks. Previews may overlap and are not an executable combined plan.
Candidates requiring earlier normalization or repair may not exist yet.

The `quality` field reuses the historical quality-counter contract: missing
cells are internal nulls. `declared_null_token_cells` separately counts raw
values matching declared null markers. Counts and issue categories do not imply
that every issue is authorized for repair. Each candidate preview is bounded to
eight samples, using the same builders and operation allowlists as cleaning.

`idac baseline --input data.csv --config schema.yaml --output runs/baseline`
explicitly applies hard-eligible local repairs and hard validation, without the
Jev gate or semantic postcheck. It needs no key and saves no invented model
distributions. Existing output directories are rejected. Hard failures produce
a nonzero CLI exit and a saved summary containing the failures; failed proposals
are not committed, and exported data contains only validated changes.

Baseline artifacts retain `cleaned.csv`, `removed_rows.csv`, `issues.json` and
`baseline.json`, and add `snapshot.json`. The summary adds `artifact_version: 2`,
`rows`, `input_hash` and `snapshot_hash` while retaining previous summary fields.
The snapshot contains original row identities and internal nulls. It is a
baseline artifact, not a full Jev run: `inspect` and `rollback` still require
the manifest and version history produced by `clean`.

## Baseline evaluation integrity

For v0.2 baselines, `evaluate` checks source/config hashes, snapshot hash, schema,
ordered surviving/removal identities, row lengths and both CSV exports. A missing
or altered snapshot with a v0.2 summary is an error. Hashes check consistency of
local artifacts; they are not signatures or external proof of provenance.

For v0.1 exports, a complete `removed_rows.csv` ledger can recover surviving
identities by excluding removed IDs from the original order. Results label that
mapping as legacy; CSV alone cannot distinguish a null from an empty string.
Without enough identity evidence, evaluation keeps quality counts and reports
cell/duplicate metrics as unavailable. It does not invent new row identities.
Regenerate a baseline with v0.2 for exact null semantics and checked snapshots.

## Compatibility and migration

- Python support expands from 3.11 to 3.11–3.13. The default repository pin stays
  on 3.11; use `uv sync --locked --python 3.12` and `uv run --python 3.12 ...`
  to use Python 3.12. The lock retains existing dependency versions.
- `examples/run_baseline.py` continues to accept the same input/config/output
  options and re-exports `BaselineRunner`. Its implementation now lives in the
  installed package, so wheel users can call `idac baseline` directly.
- `idac clean`, `inspect`, `evaluate` and `rollback` retain their existing flags.
  Historical Jev runs require no conversion. Baselines whose source or schema
  differs from the evaluated run are rejected when hashes are available.
- No new model, operations, automatic fallback, probability assumptions or
  decision thresholds are introduced. The API key is still required for `clean`.

## Acceptance checks

The offline suite covers read-only profiling, API-call blocking, protected and
disallowed cells, non-overwrite behavior, baseline hard failures, snapshot/null
preservation, interior duplicate deletion, altered artifacts, legacy identity
recovery and missing-ledger suppression. Existing cleaning, gate, storage,
request, report and replay tests remain part of the same suite.

```bash
uv sync --locked
uv run pytest -q
uv run ruff check src tests examples scripts
uv run python scripts/check_environment.py
uv build
```

Local verification on 2026-10-02:

- Python 3.11.16 and 3.12.14: **136 passed** on each interpreter; Ruff and
  environment imports/SDK question construction passed without API calls.
- Source distribution and wheel build passed. A separately installed wheel
  passed `--version`, JSON profiling and baseline cleaning from outside the
  source checkout; the baseline produced 200 rows, 10 removals and seven commits.
- CI adds an offline 3.11/3.12/3.13 matrix. Python 3.13 is covered by that
  configured matrix rather than a recorded local execution. The live v0.1
  measurements remain historical and were not repeated for this release.
